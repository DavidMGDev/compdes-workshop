Glosario de tecnologías

Taller COMPDES 2026 · Seguridad de agentes MCP/RAG para PyMEs

Qué es cada tecnología, para qué se usa aquí, en qué momento del taller aparece, y su relación con Onyx —el producto que es el centro de la propuesta de valor—. La mayoría gira en torno a Onyx: es lo que una PyME despliega, y todo lo demás es lo que lo hace útil (y atacable).

Relación con Onyx:

Núcleo es Onyx o Onyx lo usa directamente
Soporte alimenta o rodea a Onyx Marco / Independiente no depende de Onyx

Preparación (antes de la Hora 1)

NúcleoSetup + todo
Docker / Docker Compose

Ejecuta programas en "contenedores" aislados, sin instalarlos a mano.

Aquí: levanta la base de datos de la PyME y el propio Onyx Lite. Onyx corre enteramente sobre Docker.

SoporteSetup
Git / GitHub

Control de versiones y alojamiento de código.

Aquí: descargar el taller y clonar el repositorio de Onyx para desplegarlo.

SoporteSetup + todo
Python

El lenguaje en que está escrito el código del taller.

Aquí: ejecuta el servidor MCP, los scripts y el agente CLI (Ruta B). El servidor MCP en Python es lo que le da herramientas a Onyx.

Hora 1 — Construir (el valor de negocio)

NúcleoHora 1–3
Onyx (Lite, Community Edition)

Plataforma de IA de código abierto (antes Danswer, licencia MIT): chat web, RAG sobre documentos y agentes con herramientas.

Aquí: es el agente de la PyME. Se abre en localhost:3000 y es la cara "de producto" del taller. Modo Lite = ligero (~2 GB RAM).

NúcleoTodo
Gemini gemini-3.5-flash-lite

El modelo de lenguaje (el "cerebro") de Google que razona y decide qué herramienta usar.

Aquí: el modelo con el que se configura Onyx. Económico y afinado para uso de herramientas.

NúcleoTodo
Endpoint compatible con OpenAI

Una interfaz estándar; permite que el mismo código hable con Gemini, OpenAI u otros sin cambios.

Aquí: es cómo Onyx (y el agente CLI) se conectan a Gemini: …/v1beta/openai/.

NúcleoHora 1–3
MCP (Model Context Protocol)

Estándar abierto (de Anthropic) para conectar un agente con "herramientas" externas.

Aquí: el corazón del taller. Nuestro servidor MCP expone tres herramientas (SQL, actualizar stock, validar enlace). Onyx las registra como una Acción MCP apuntando a host.docker.internal:9000/mcp.

NúcleoHora 1–3
FastMCP

La librería de Python que implementa el servidor MCP con pocas líneas.

Aquí: corre en dos modos — stdio (para el agente CLI) y --http (para que Onyx lo alcance por red).

NúcleoHora 1–2
RAG (sentence-transformers)

"Generación aumentada por recuperación": deja que el agente cite documentos que no estaban en su entrenamiento.

Aquí: recupera fragmentos de los PDF de política. En la Ruta A lo hace Onyx (documentos subidos); en la Ruta B lo hace rag.py. También es el vector del Lab 2.1.

SoporteTodo
PostgreSQL

Base de datos relacional.

Aquí: los "datos joya" de la PyME (inventario, clientes, columnas sensibles). Onyx la consulta a través de las herramientas MCP; además Onyx Lite guarda su propio estado en Postgres.

SoporteHora 1
reportlab / pdfplumber

Generan y leen archivos PDF.

Aquí: crean los PDF de política que luego se suben a Onyx para el RAG.

Hora 2 — Romper (red teaming)

MarcoHora 2
OWASP Top 10 para Aplicaciones Agénticas (ASI)

La lista de referencia de los diez riesgos más importantes específicos de agentes de IA (de OWASP, los mismos del "Top 10" web).

Aquí: cada ataque se etiqueta con su código ASI… para conectarlo a un estándar de industria. Aplica al agente Onyx.

MarcoHora 2
MITRE ATLAS

El catálogo de MITRE de tácticas y técnicas adversarias contra sistemas de IA/ML — la versión "ATT&CK" para IA.

Aquí: mapea cada ataque a una táctica (Acceso inicial → Ejecución → Exfiltración…). Es una taxonomía, no un programa que se instala.

Ataca a OnyxHora 2
PyRIT

Herramienta de Microsoft para red-teaming automatizado de IA generativa.

Aquí: automatiza el jailbreak multi-turno Crescendo (Lab 2.3) contra la API de Onyx o el wrapper HTTP.

Ataca a OnyxHora 2
Garak

Escáner de vulnerabilidades de LLM: lanza cientos de "sondas" conocidas y reporta qué pasó — el "nmap de los LLM".

Aquí: escaneo amplio (Lab 2.5) contra el endpoint del agente. Es el lab más costoso; se acota a una familia de sondas.

TécnicaHora 2
Crescendo

No es una herramienta, es una técnica: un jailbreak multi-turno que escala poco a poco para que cada paso parezca razonable.

Aquí: se hace a mano en el chat de Onyx (Lab 2.3); PyRIT puede automatizarlo.

SoporteHora 2–3
FastAPI / uvicorn

Framework para exponer código como un servicio web.

Aquí: http_wrapper.py expone el agente por HTTP para que los escáneres (Garak/PyRIT) lo ataquen. Es una alternativa a la propia API de Onyx.

Hora 3 — Blindar (defensa)

SoporteHora 3
Herramientas MCP endurecidas + defensas

Servidor MCP seguro, roles SQL de mínimo privilegio, aprobación humana (HITL), enrutador semántico y fijado de descriptores.

Aquí: se re-registra el servidor MCP seguro en Onyx y se repiten los ataques → ahora fallan. Protegen justamente las herramientas que Onyx invoca.

IndependienteHora 3
Promptfoo

Framework para evaluar y probar LLM de forma automatizada.

Aquí: corre los ataques como pruebas de regresión en CI, para que una vulnerabilidad ya corregida no reaparezca.

IndependienteHora 2–3 (opcional)
Node.js

Entorno de ejecución de JavaScript.

Aquí: solo se necesita para instalar/correr Garak y Promptfoo. No participa en Onyx ni en la Hora 1.

En una frase: el taller abre con Onyx como la IA que una PyME sí puede desplegar; el modelo (Gemini), las herramientas (MCP), el RAG y la base de datos son lo que lo vuelven útil — y, en las Horas 2 y 3, lo que se ataca y se blinda.
